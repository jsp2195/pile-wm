# Decisions and experiments

- The repository initially contained only LICENSE. The user explicitly requested implementation, so source changes are authorized despite the earlier onboarding-only scope.
- Python 3.11, uv lockfile, dataclasses and YAML; package/artifact caches live under /workspace because the home directory is read-only in the cloud machine.
- No CUDA device is available. Validate CPU smoke; small GPU experiments and full experiments remain unrun.
- Simulator uses simultaneous Jacobi disc contact projection with per-particle contact-count damping, wall clamping, and five substeps of at most 0.008 table units. Diagonal actions are norm-limited to 0.04. Contacts are geometric and overdamped, without inertia or an assumed friction law.
- Initial configurations mix 20% scatter with 1–3 Gaussian clusters, then settle with 300 projection iterations. State IDs preserve particle count.
- Renderer tiles particles to bound temporary memory and runs with native PyTorch on the selected device. Ground-truth evaluation maps use bilinear count splatting, making particle-density mass explicit.
- Smoke is a plumbing/measurement budget, not evidence of learned physical competence. No encoder substitution is permitted; tiny test stubs will be limited to unit tests.
- Milestone 1 validation: `python -m pytest -q` passed 4 tests on CPU; `python -m scripts.random_push --config configs/smoke.yaml` produced a 40-frame GIF. PyTorch 2.14.1 reports CUDA and MPS unavailable. Installed the normal portable PyTorch package (including CUDA runtime dependencies) so the lockfile also supports compatible GPU hosts.
- Dataset-wide auditing found a missed simulator failure in smoke trajectory 14 at step 17: maximum penetration 0.00133023 exceeded the configured 0.0005 tolerance. The initial short simulator tests passed but were insufficient. Interrupted the first dataset generation; its partial files are superseded by regeneration. Added a fixed-action regression and independent per-environment convergence checks with extra contact sweeps, freezing converged environments to preserve batch equivalence. Unresolved penetration now raises rather than silently saving invalid geometry.
- Official DINOv2 ViT-S/14 checkpoint GET and HEAD requests both failed with HTTP 403 at the cloud proxy. The configured custom allowlist was empty and its package-manager preset omitted dl.fbaipublicfiles.com. Saved that domain addition without changing presets, plus reusable install_script/start_skill. Draft saving is confirmed but does not apply or publish network changes. Per the user's explicit instruction, stop before milestone 3 and do not substitute an encoder.

- Milestone 2 validation: all 8 tests passed in 12.69 seconds on CPU. Regenerated smoke with the corrected solver: 32 trajectories, 1,280 transitions, 26/3/3 trajectory split. Full saved-state audit passed; max penetration 0.00012286193668842316 against tolerance 0.0005. Data generation took 291.572669304 seconds, including concurrent CPU work during part of the run; this is not an isolated benchmark. The few-minute end-to-end target is not met; profile solver work and thread contention next. Regenerated 40-frame 224px random-pushing GIF. Frozen installation script was executed successfully a second time.
- Continuation: the official DINOv2 checkpoint now downloads through verified HTTPS. SHA-256 is b938bf1bc15cd2ec0feacfe3a1bb553fe8ea9ca46a7e1d8d00217f29aef60cd9; subsequent loads verify it. Use timm's equivalent ViT-S/14 architecture with strict weight loading and original DINOv2 bicubic positional interpolation (offset 0.1, antialias disabled). CLS is used internally but never passed to the predictor. Real-weight integration check produced deterministic frozen [1,256,384] patch tokens on CPU.
- Milestone 3: normalization is fitted only to seeded training-frame samples (32 smoke frames, 8192 tokens); validation/test never update it. Decoder output is nonnegative count density plus unit-mass pusher supervision. Decoder detaches inputs at its boundary; a unit test verifies that predictor parameters receive no gradients. Smoke decoder training ran 20 steps: final train loss 0.02328719, validation loss 0.02619214, 6.09 seconds in this run. This does not establish a high-quality evaluation decoder; report its reconstruction quality alongside dynamics metrics.
- Milestone 4: deterministic residual transformer has 11,191,680 parameters (6 layers, width 384, 6 heads). Actions label outgoing transitions and are embedded on every token of their frame. The block mask permits all tokens within a frame and past frames, and excludes future frames. Three teacher-forced predictions and a differentiable three-step autoregressive rollout are trained jointly. Offline tests cover mask semantics, action conditioning, autoregressive consumption, gradient flow, and parameter budget.
- Smoke uses four predictor updates solely to exercise the pipeline. Training measured 2.43 seconds in online rendering/encoding versus 8.71 seconds in predictor optimization; encoding was not the bottleneck, so no latent cache was added. Statistics/decoder/predictor never fit held-out trajectories. Small/full budgets are explicit in YAML and remain unrun.
- Initial smoke held-out evaluation: failed to beat copy-last-frame; action-shuffle relative gap was 0.00350108 (0.35%), below the predeclared 5% threshold. Counterfactual latent divergence correlation was 0.5011485 across three pairs; this tiny sample is not proof of physical counterfactual accuracy. Fixed density occupancy threshold is 0.1 particle-count units. Counterfactual particle-density correlation is reported separately, and zero-variance correlations are null, not passing. Do not tune these metrics in response to failure.
- Milestone 5: CEM uses bounded continuous proposals, an explicit no-op candidate, elite refitting, and MPC warm starts. Learned CEM receives only latent history, past actions, and encoded goal; its cost object has no simulator/state access. Oracle uses the same CEM and standardized latent terminal cost but simulates candidate transitions. Candidate batches are chunked for bounded inference memory. All reported task metrics use true particle positions.
- Gather goal is a centered nonoverlapping hexagonal disc packing, with the pusher parked at (0.5,0.95). Its image introduces a pusher-position component in the prescribed latent cost; do not pretend that this cost is exactly Chamfer or gather fraction. Reach goals use hidden correlated random sequences from the same start. Smoke has only three executed actions and two episodes per task/policy; some reach goals barely displace particles. A reach success additionally requires halving initial Chamfer, so a nearly unchanged pile is not counted as successful merely for being close. Gather success requires 80% inside the fixed geometric disc. Small/full have 50 paired episodes, 20 executed actions, and larger CEM budgets.
- First smoke planning run (two episodes, CPU): learned reach Chamfer 0.00107412 +/- 0.00105618 SE versus no-op 0.00009093 +/- 0.00007299; learned gather fraction 0.2100 +/- 0.1250 versus no-op 0.2075 +/- 0.1225. No policy met the declared task success criteria in these episodes. Learned planning advantage is not demonstrated. The smoke sample is insufficient for efficacy claims. CEM unit tests recover a known quadratic optimum, confirm reproducibility, verify model-only rollout costs, and replay hidden reach actions exactly.
- CPU performance: cache static pair masks/tie directions and check contact convergence every four sweeps. Freeze each converged environment independently at tolerance/8, with the existing final tolerance and dense-contact regression unchanged. This reduces redundant work without weakening the configured 0.0005 penetration requirement. Bumped simulator data version to 2 and regenerated smoke rather than mixing old and new dynamics. The full dataset audit still passes. Interrupted generation invalidates its manifest before overwriting states.
- Reporting is generated directly from raw metrics, with fixed color scales for true/predicted density GIFs and a decode-true-latent reconstruction control. The complete pipeline runs offline tests and all stages sequentially, reseeding each stage so standalone runs and pipeline runs are reproducible. Only compatible state datasets may be reused; every model stage reruns. Source hashes and resolved configuration accompany the report.
- Portability checks: normalization accumulates in CPU float64 because MPS does not support float64 tensors. Set deterministic CUDA workspace configuration before device initialization. These changes support the intended paths but do not establish GPU/MPS validation on this CPU-only machine. A writable XDG cache avoids fontconfig warnings from the read-only home directory.
- Milestone 6 end-to-end validation: `python -m scripts.pipeline --config configs/smoke.yaml --regenerate` completed every stage and report in 181.313665 seconds on CPU; data generation took 90.003063 seconds. The full state audit passed (maximum penetration 0.0001237802 < 0.0005). A second `uv run --frozen python -m scripts.pipeline --config configs/smoke.yaml` reused only the state dataset and completed in 94.805655 seconds, with 19 offline tests passing. Decoder loss, training results, every rollout/intervention metric, and every physical planning outcome matched exactly across runs after excluding timing fields. Archived both run metrics and a reproducibility check in reports/smoke/.
- Final smoke results after simulator optimization: mean latent rollout MSE 0.372051 versus copy 0.216654; action-shuffle relative gap 0.00279078 (0.279%, fails 5% threshold); counterfactual latent correlation 0.560351 but particle-density correlation -0.666483; decoded final mass drift -8.6105%. These are failures of the empirical world-model checks, not success disguised by plausible images. The decode-true-latent final IoU is 0.400845, so decoder quality also limits physical interpretation.
- The updated solver changes tiny residual settling: final smoke reach success is 1/2 for learned, oracle, and no-op, while gather is 0/2 for all methods. The raw reach metric remains worse for learned than no-op, and paired planning advantage is not demonstrated. This replaces the earlier zero-success result from simulator version 1. Success thresholds and evaluation metrics were not changed after seeing these outcomes; tiny reach goals and a two-episode smoke budget remain explicit limitations.
- Every requested figure and both GIFs were generated from the real smoke run, image files were decoded successfully, and rollout/planning figures were visually inspected. Small/full and GPU/MPS execution remain unrun; no GPU is available. Flow matching is intentionally not implemented because deterministic empirical milestones do not pass. Next priority is sufficient training and decoder quality, followed by unchanged action/counterfactual/planning controls on the 50-episode small configuration.
